# Wedding planning dashboard

Private dashboard for tracking vendors, payments and deadlines. Next.js on Vercel, Supabase (database + auth), Resend (email). No passwords: everyone signs in with an emailed link.

## What it does

- **Vendors**: contract total, paid so far, and what's left (calculated from a payment ledger).
- **Deadlines & payments**: due date, who owes it, partial payments, mark done.
- **Reminders**: a daily job emails whoever owes an item 7, 3 and 1 days before it's due. People with "copy on every reminder" get all of them.
- **People**: owner invites by email and picks, per person: role (viewer / editor / owner), which vendors they see, whether they see dollar amounts, and whether they see general deadlines. This is enforced in the database (row-level security), not just hidden in the UI.

## Setup

### 1. Supabase
1. Create a project.
2. SQL editor: run `supabase/migrations/0001_init.sql`.
3. Authentication > Sign In / Providers > turn **off** "Allow new users to sign up" (the app creates login users itself, only for invited emails).
4. Project Settings > API: copy the URL, the `anon` key and the `service_role` key.

### 2. Resend
1. Verify a sending domain (Domains).
2. Create an API key.
3. Choose a from-address on that domain, e.g. `Wedding Planning <planning@yourdomain.com>`.

### 3. Vercel
Import the repo and set these environment variables (see `.env.example`):

| Variable | Notes |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | from Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | secret, server only |
| `RESEND_API_KEY`, `RESEND_FROM` | from Resend |
| `NEXT_PUBLIC_SITE_URL` | your production URL, no trailing slash |
| `OWNER_EMAIL` | your email: the first sign-in with it creates the wedding and makes you owner |
| `WEDDING_NAME` | optional |
| `CRON_SECRET` | any long random string |

`vercel.json` schedules the reminder job daily at 14:00 UTC (8am US Central in winter, 9am in summer). Change the cron expression to taste.

### 4. First run
Open the site, enter `OWNER_EMAIL`, click the link in your email. Then add vendors, deadlines, and invite people on the People page.

### Local development
```
cp .env.example .env.local   # fill it in
npm install
npm run dev
```
To test reminders locally: `curl -H "Authorization: Bearer $CRON_SECRET" localhost:3000/api/cron/reminders`

## Design notes

- Money is stored as integer cents.
- Login links are generated by the server and sent through Resend (Supabase's own mailer isn't used). Only emails on the invite list (or `OWNER_EMAIL`) get a link, and the login form gives the same response either way.
- Reminders are logged in `reminder_log` with a unique key, so a re-run never double-sends. Moving a due date makes reminders go out again for the new date.
- Reminder emails show the outstanding amount only to the person who owes it and to copied people who are allowed to see amounts.
- Login links are single-use. Some corporate email scanners open links before the person does, which uses the link up; if someone reports "link expired", send a new one from the People page.

## Not built yet / worth knowing

- No rate limiting on the login form.
- No file uploads (contracts, invoices).
- Editors who aren't allowed to see amounts can't create payments (the form hides them).
